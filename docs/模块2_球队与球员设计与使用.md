# 模块②：球队与球员

已实现球队、球员的公开目录与详情，以及管理员维护功能。认领和实现：Codex 辅助开发，2026-10-21。代码基于仓库 `f26617691feb284c7f1f26b4f3dfefad8890134b`；姓名和学号未冒用真实组员信息。

## 开始使用

首次安装按照根目录 [README](../README.md) 初始化 Yii2、配置数据库并导入 `data/install.sql`。该安装脚本会重建表，已有数据的环境不要重复导入。模块②不修改表结构，无需额外迁移。

需要示例时，在项目根目录执行：

```powershell
mysql --default-character-set=utf8mb4 -u root -p worldcup --execute="SOURCE data/demo_teams_players.sql"
```

脚本补充阿根廷、法国、五位球员、部分 2022 年名单和决赛六粒进球。它可以重复执行，不覆盖已有资料；若已有该届决赛，不追加进球。该数据集仅用于功能演示，球员统计显示的是已录入数据，不能当作完整世界杯生涯统计。

按项目原有方式启动前后台：

```powershell
php yii serve --port=8080 --docroot=frontend/web
php yii serve --port=8081 --docroot=backend/web
```

| 入口 | 路由 | 使用者 |
|---|---|---|
| 球队目录、名称/代码搜索、大洲筛选 | `index.php?r=team/index` | 游客 |
| 球队详情、按届次查看名单 | `index.php?r=team/view&id=1` | 游客 |
| 球员目录、姓名/国籍搜索、球队/位置筛选 | `index.php?r=player/index` | 游客 |
| 球员详情、履历、各届进球与助攻 | `index.php?r=player/view&id=1` | 游客 |
| 球队后台维护 | 后台 `index.php?r=team/index` | 管理员、超管 |
| 球员后台维护 | 后台 `index.php?r=player/index` | 管理员、超管 |

示例 ID 仅适用于新建数据库，已有数据时从目录进入详情。两套布局都已添加导航入口。

## 维护资料

1. 登录后台，进入“球队管理”或“球员管理”。
2. 点击“新增”，填写资料后保存；列表操作列可查看、编辑、删除。
3. 球队名称和非空代码不能重复；代码自动转大写，空代码保存为 NULL。球员允许重名，出生日期必须真实且不晚于今天。
4. 简介按纯文本显示。图片填写前台 `images/` 或 `uploads/` 下的图片相对路径，例如 `uploads/player/messi.jpg`，由维护者预先放置文件；本模块不提供文件上传功能。
5. 球员代表哪支球队、每届号码和位置由模块③的 `squad` 名单维护，此处不把国籍当作球队归属。

删除必须使用 POST 并通过 Yii2 的 CSRF 校验。有比赛、名单、进球或助攻关联时，数据库外键会拒绝删除，并显示可读提示。存在球队/球员留言时，模型额外阻止删除，避免多态留言成为孤立数据。

## 设计与协作接口

| 层 | 文件 | 职责 |
|---|---|---|
| 公共模型 | `common/models/Team.php`、`Player.php` | 字段校验、跨届名单、球员履历、统计和留言删除保护 |
| 查询模型 | `common/models/TeamSearch.php`、`PlayerSearch.php` | 前后台共用参数校验、过滤、排序、每页 12 条的分页 |
| 前台控制器 | `frontend/controllers/TeamController.php`、`PlayerController.php` | 列表与详情；无效 ID、无效届次返回错误 |
| 后台公共控制器 | `backend/components/CatalogController.php` | 管理员鉴权、增改删流程、数据库冲突处理 |
| 后台控制器 | `backend/controllers/TeamController.php`、`PlayerController.php` | 绑定各自模型和查询模型 |
| 视图 | 两端的 `views/team/`、`views/player/`、`views/catalog/` | 页面与可复用表单；所有资料文本转义输出 |
| 图片路径校验 | `common/validators/AssetPathValidator.php` | 仅接受站内图片相对路径，拒绝越界与外部 URL |

查询流程：请求参数 → Search 模型校验 → 参数化数据库查询 → 分页数据提供器 → 目录视图。参数无效时展示错误和空结果，不放宽为全库搜索。

后台保存流程：登录和角色检查 → Yii CSRF 校验 → 模型字段校验 → 保存 → 重定向详情。唯一约束冲突返回表单错误。后台删除流程额外检查多态留言，并捕获历史数据外键冲突。

`Team::rosterQuery($tournamentId)` 通过 `squad.player_id` 子查询找球员，同一球员跨届只出现一次。球员的每届履历仍逐届列出，球队详情可以按届次过滤。`Player::statistics()` 聚合 `goal`、`game`、`tournament`，只统计 `game.status = 2`、`is_shootout = 0`、`is_own_goal = 0` 的记录；非点球大战的点球正常计入。模块③录入新数据后，页面统计自动更新。

此设计说明是模块②的交付补充；全队设计文档仍需整合其他模块和最终图示。可选球员动态图未纳入本次实现。

## 验收与复现

实际验收环境：Windows，PHP 8.0.30，Yii2 2.0.32，MariaDB 10.4.32。本次没有用 MySQL 8.0 或 PHP 8.2 重跑验收。

- 31 个新增/修改 PHP 文件语法检查通过。
- 数据库回归 24 项通过：跨届去重、球队归属、日期和图片校验、进球/助攻口径、删除保护、字段赋值和编辑持久化。
- HTTP 验收 36 项通过：前台搜索与详情、后台权限、两种实体的增删改查、输出转义、CSRF、GET 删除拒绝、重复记录和历史关联提示。
- 演示 SQL 连续执行两次成功；桌面与手机视口检查结果见 `output/playwright/`。

数据库回归脚本只连接名称精确为 `worldcup_module2_test` 的数据库。请先**单独创建空测试库**，将 `install.sql` 中的建库与 `USE` 语句改为这个测试库，再导入；不要在业务库执行。

```powershell
$env:WC_TEST_DSN = 'mysql:host=127.0.0.1;port=3306;dbname=worldcup_module2_test'
$env:WC_TEST_USER = 'root'
$env:WC_TEST_PASSWORD = '自己的测试库密码'
php tests/module2/run.php
```

HTTP 验收需要 `requests` 和 `beautifulsoup4`，前后台都必须配置为上述测试库。先导入演示 SQL，并为测试库的 `admin`、`demo` 设置同一个仅用于测试的密码，再启动两套本地服务。

```powershell
$env:WC_TEST_FRONT = 'http://127.0.0.1:8080'
$env:WC_TEST_BACK = 'http://127.0.0.1:8081'
$env:WC_TEST_ADMIN_PASSWORD = '上一步设置的测试密码'
python tests/module2/http_smoke.py
```

HTTP 脚本以新建测试库的演示 ID 为前提，使用 `admin`、`demo` 验证权限，并临时新增、修改和删除验收数据。数据库脚本中的测试修改在事务结束时回滚；HTTP 验收应始终使用可重建的测试库。
