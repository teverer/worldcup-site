# 设计改造 · 01 感觉与工作流（交接）

> 用途：这是 00 总纲的“感觉层”补充。新会话 / compact 后先读本文件 + 00 总纲第 14 节，不要只按页面规格机械实现。
> 状态：2026-11-23。第 3 步规格已定稿；上一轮由另一个对话实现的效果不理想，需要按本文件重做 / 修正。

## 1. 用户要的感觉（最高优先级）

- 关键词：**夜场、深蓝 / 夜蓝黑、球场深绿、红、紧张、刺激、野性、竞技、张弛有度**。
- 金色：只给冠军 / 纪录 / 奖杯，表现“辉煌”；不要到处用。
- 平淡处：用冷纸 / 灰 / 留白让读者缓和；不要整站一直燃。
- 不是：八卦站、榜单站、数据后台、模板站、直播站。
- 记忆是感觉的副产品：先让人有感觉，再记住一个比分 / 冠军 / 夜晚。
- 反例：四个瞬间 / 最大比分差 / 花絮清单 / 英文 eyebrow / 满屏白卡 / 圆角卡 + 阴影 / 渐变占位图 / 每个链接加箭头 / 大卡片表示一个国家 / PAR、FRA 代码。
- 参考：根页 `frontend/views/site/index.php` + `frontend/web/css/root-wall.css` 是“感觉”的基准；新页面要和它同一气质。

## 2. 已定设计决策（不要重新讨论）

- **根页 = 记分牌墙**，不是 dashboard；11 届，最新一块打亮。
- **届次页 = 一个页面，一个舞台**：
  - 紧凑深色记分牌头（年份 / 冠军 / 决赛 / 4 项 facts）。
  - 本地 tab：淘汰赛 / 小组赛 / 统计；讨论在右侧 + 评论数；文字下划线，不用胶囊。
  - 一次一个视图；原生链接 + CSS `:target` / `:has`；保留 `#knockout` / `#groups` / `#charts` / `#comments`；无 JS 全部可见。
  - 淘汰赛 = **纵向树**：决赛在最上方，半决赛 / 1/4 / 1/8 依次向下；从 **16 强**开始；2026 的 1/16 折叠在下方。
  - 卡片：中文名 + 比分；不用代码；无加时 / 点球徽章；无“详情”行；整卡可点；决赛最大、冠军金色；冠军路径金 / 绿线。
  - 小组赛：12 / 8 / 6 组积分表网格，出线标记，队名链球队页。
  - 统计：只保留现有三张图；冷纸底；金给第一，红给决胜；不加新图。
  - 讨论：舞台下方单列，去掉 `COMMUNITY` eyebrow。
  - 不做：四个瞬间、最大比分差、横向旧树、104 场大表、新图。
- **颜色**：夜 `#071A26`，看台 `#0C2431`，球场绿 `#0E3B2E`，冷纸 `#E9EDE9`，泛光 `#F3F6F2`，墨 `#0B1A22`，红 `#C8102E`，金 `#C9A227` / `#E8C766` / `#8A6500`，绿动作 `#146B45` / `#7FC8A9`。
- **字体**：Saira Condensed 只给数字 / 年份 / 比分；中文系统黑体，标题 700–800、紧字距；正文系统字体。
- **密度**：根低 → 届次高 → 比赛低 → 球队 / 球员中 → 资讯低；一屏最多 3 级字号；一个主按钮。
- **规则是下限，不是上限**；与感觉冲突时先提案突破并记录。

## 3. 工作流（每个实现会话必须遵守）

1. `git status`；确认当前分支和工作区；不要顺手提交别人的改动。
2. 一个会话只负责一个页面 / 一组文件；先从 `dev` 开 `feature/xxx`；不要在 `dev` 上直接改。
3. 改动前先读本文件 + 00 总纲第 14 节 + 根页代码；**先给计划，再动手**。
4. 只改页面视图 / 专属 CSS / 必要只读数据；不改数据逻辑，不加新图，不编造数据。
5. 自检：`php -l`；`curl` 200；**1280 / 1366 / 1440** 截图（PC 优先）；390 只做不溢出兜底；检查焦点 / reduced motion / 空 / 加载 / 错。
6. 小步 commit；更新 00 总纲第 8 / 9 / 12 / 14 节；汇报“改了什么 / 下一轮改什么”。
7. 多会话：动手前声明文件边界；冲突先沟通；不要两个会话改同一文件。
8. 子代理只做可验证的局部任务（读文件、QA、截图检查）；视觉判断和页面落地留在主会话。

## 4. 评审：什么叫“好”

- 第一眼有夜场感，不是后台；深色只给入口 / 身份 / 纪录；数据区是冷纸。
- 一屏一个主角；决赛在顶；晋级树一屏；不横向滚动。
- 中文名可读；没有英文代码；没有徽章 / 详情行 / 大卡片。
- 金色只给冠军 / 纪录；红色只给决胜；绿色只给动作。
- 层次：我在哪 / 这里有什么 / 下一步点哪；每页一个主操作；不留死路。
- 与根页并排看，像同一个站；不是“另一个模板”。

## 5. 上一轮效果差的原因（避免重犯）

- 只按页面规格机械堆模块，没有抓住“感觉”；结果像 CMS / 后台。
- 保留了旧的横向树 / 四个瞬间 / 代码 / 徽章等被否决的元素。
- 没有先看根页的质感，没有 1280 / 1366 / 1440 截图自评，没有和根页并排比较。
- 纠正：先读本文件，先给计划，先做一版“能看”的局部（头 + 树）再扩展；每个决定问“这是不是根页的气质”。

### 5.1 第 3 步上一版的具体问题（2026-11-23）

截图：`runtime/qa/step3-knockout/tournament-view-11-1440.png`、`runtime/qa/step3-groups/tournament-view-11-1440.png`、`runtime/qa/step3-charts-click2/tournament-view-11-1440-tdpanelstats.png`。

- **淘汰赛**：树太小，缩在一张白色大卡里；左侧“决赛 / 半决赛 / 1/4 / 1/8”标签让它像表格；决赛不突出；1/8 八列太窄，名字小；右侧和下方大量空白；没有夜场感。
- **头部**：4 项 facts 太小；tab 太弱；“记分牌墙”小标像说明文字。
- **小组赛**：3 列在 1200 宽下每表太窄，L 组右列被挤；1280 会更紧。
- **统计**：结构可以；组别选择是胶囊，可改成文字 chips；图表本身可以。
- **结论**：不是结构问题，是**舞台的视觉执行**。下一轮只做三件事：
  1. 淘汰赛舞台改成深色夜场：`--night` 背景，决赛卡大、冠军金色；树用满舞台宽度；去掉左侧轮次标签，改成每行上方的小标题或不放；1/8 八列均分；连线泛光 / 金色，冠军路径亮、其他暗。
  2. 头部 facts 放大，tab 加强；小组 / 统计保持冷纸浅色。
  3. 小组赛改 2 列（或 3 列但更宽），保证 1280 不挤。
- 不做：新结构、新模块、新图；先把这一版的夜场感做出来。
