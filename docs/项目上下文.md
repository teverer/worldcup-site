## 二、产品定位(决定信息取舍)

这不是比分直播站,而是**已结束赛事的历史档案 + 社区讨论**。

因此:

- 访客关心:谁夺冠、怎么夺冠、有哪些球队和球星、可以讨论
- **不在列表页展示**:比赛时间、场地、完赛状态(只在比赛详情页保留)
- 首页负责"入口与概览",届次页负责"完整殿堂",两者不重复堆信息
- 届次详情页首屏是**晋级图**,让"国家逐轮厮杀"一眼可见

## 三、关键决策记录

### 1. 使用 Yii2 advanced 模板

老师环境里已有 advanced 项目(`D:\Program Files\xxxampp\htdocs\advanced`),直接复用,`vendor/` 已提交进仓库,队友 clone 后无需 Composer。

### 2. 比赛表叫 `game`,不叫 `match`

`match` 是 **PHP 8 保留关键字**,按表名生成的模型类 `class Match` 无法编译,Gii 会直接失败。因此全库统一 `game`,`goal.game_id`。这是本项目最重要的命名约定。

### 3. 数据库 14 张表,精简过一次

最初设计 17 张,后来:

- 删除投票相关 `vote` / `vote_record`
- 删除 `stadium` 表,比赛场地改为 `game.venue` 文本
- `comment_like` 升级为核心表
- 最终 14 张,满足"表数量 >10"

### 4. 留言/点赞需要登录

前台注册登录直接复用 advanced 模板自带的那套。`comment.user_id` 非空,点赞用 `UNIQUE(comment_id, user_id)` 防重复。

### 5. 乌龙球归属用 `goal.team_id`

不靠 `player_id + squad` 反推,因为乌龙球会算给错误球队。约定:`goal.team_id` 是**进球归属队**,乌龙球填受益方;`player_id` 填乌龙球员。

### 6. 胜场积分随届次变化

`tournament.win_points`:1986/1990 为 **2 分**,1994 起为 3 分。积分榜必须读取该字段,不能硬编码。

### 7. 晋级图采用轮次列 + 汇流连线

- 数据由 `TournamentDetail` 一次准备
- 连线箭头实测下一轮卡片中心,避免布局变化导致错位
- 三四名决赛独立于决赛列,避免把决赛卡片挤偏
- 悬停/键盘聚焦显示进球时间线;点击进比赛详情
- 无 JS 时仍可读比分(渐进增强)

### 8. 页面设计归队长,不属于模块①

2026-11-17 调整:模块①只负责团队展示、后台信息编辑、作业下载页;框架、导航、首页、全局样式由队长统一负责,避免多人各写一套视觉。

## 四、数据管线

### 来源

| 届次 | 来源 | 许可 |
|---|---|---|
| 1986–2022(604 场) | [openfootball/worldcup](https://github.com/openfootball/worldcup) + [martj42/international_results](https://github.com/martj42/international_results) | CC0 |
| 2026(104 场) | openfootball `2026--canada-usa-mexico/` | CC0 |

两个来源逐场交叉校验:604/604 场日期、球队、比分一致;进球数量一致;点球/乌龙标记差异为 0。

### 当前规模

11 届 / **708 场** / **2045 球** / 83 队 / 4282 名球员 / 344 条参赛队 / 5685 条名单。

### 导入顺序

```bash
mysql -u root -p < data/install.sql
mysql -u root -p worldcup < data/real_worldcup_data.sql
mysql -u root -p worldcup < data/real_worldcup_2026.sql
```

两个数据文件都是幂等的。

### 已知缺口

- 教练、FIFA 排名、最终名次:无可靠来源,`NULL`
- 2026 名单:只含 190 名进球者,非完整 26 人
- 2026 助攻:数据源没有,`NULL`
- 点球大战:只有总比分,无逐轮主罚者,因此没有 `is_shootout=1` 的进球行
- 补时进球按基础分钟记录(45+3' 记 45)

## 五、系统架构

### 应用划分

| 应用 | 端口 | 职责 |
|---|---|---|
| `frontend` | 8080 | 访客浏览、注册登录、留言、资讯 |
| `backend` | 8081 | 管理员登录与全部 CRUD |
| `console` | — | 命令行(yii 脚本) |
| `common` | — | 模型、公共组件、共享配置 |

### 目录职责

- `common/models/` —— 每张表一个 ActiveRecord 模型 + 后台 Search 模型
- `frontend/controllers/` —— Site、Team、Player、Tournament、Game、Chart、News、Comment
- `backend/controllers/` —— Site + 10 个管理控制器
- `frontend/views/` —— 按控制器分目录;局部视图以 `_` 开头
- `frontend/web/` —— Web 根目录(`index.php` 由 `php init` 生成,不入库)
- `frontend/web/uploads/` —— 上传图片(队徽、球员照片、资讯封面)
- `data/` —— 建库脚本、真实数据、团队/个人作业

### 配置文件

- `common/config/main.php` —— 共享配置;含 MySQL 8 兼容修复:
  `PDO::ATTR_CASE => PDO::CASE_LOWER`
- `common/config/main-local.php` —— 数据库账号密码,**gitignore**
- `frontend/config/main-local.php` —— 前台本地配置(已关闭 debug 工具栏,仅本机生效)

## 九、环境坑与处理

| 现象 | 原因 / 处理 |
|---|---|
| `Undefined array key "constraint_name"` | Yii 2.0.32 + MySQL 8;已在 `common/config/main.php` 加 `PDO::ATTR_CASE => PDO::CASE_LOWER` |
| `class Match` 语法错误 | `match` 是 PHP 8 关键字;一律用 `game` |
| MySQL 连不上 | MySQL80 服务未启动;需管理员执行 `net start MySQL80` |
| git 推送 TLS 错误 | Clash 代理节点抖动;重试或切节点,必要时直连 |
| `/tournament/index` 打不开 | 未启用 prettyUrl,用 `index.php?r=tournament%2Findex` |
| CSS 改了不生效 | 删除 `frontend/web/assets/` 下哈希目录,刷新重新发布 |
| 页面右下角调试图标 | 前台 `main-local.php` 已关闭 debug;其他环境需自行关闭 |
| LF/CRLF 警告 | Windows 正常提示,不影响提交 |
