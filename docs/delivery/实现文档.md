## 一、项目概述

“世界杯40年概展”是使用 Yii2 advanced、PHP 与 MySQL 实现的世界杯主题数据门户。系统覆盖 1986–2026 年世界杯，提供届次、球队、球员、比赛、进球、统计图表、资讯、团队介绍、作业下载和社区留言功能。

项目采用前后台分离结构：

- 前台负责公开数据展示、用户注册登录和社区互动。
- 后台工作台面向管理员，维护赛事、球队球员、内容和团队主页。
- 公共模型与组件位于 `common/`，前后台共享同一套数据库和业务规则。

## 四、系统架构

### 4.1 MVC 调用链

```text
浏览器请求
  -> Controller 路由、登录状态和角色校验
  -> Model / Search 参数校验、查询和保存
  -> View 页面渲染与输出转义
  -> Active Record / Query 访问 MySQL
```

### 4.2 应用划分

- `frontend`：首页、届次、比赛、球队、球员、资讯、团队主页及留言。
- `backend`：管理员登录、工作台及各业务管理模块。
- `common`：公共数据模型、缓存、路径校验、留言组件、全站 UI 资源和确认框。

### 4.3 路由形式

项目采用 Yii2 默认路由形式：

```text
index.php?r=controller/action
```

例如：

```text
index.php?r=tournament/view&id=10
index.php?r=news/index
```

## 六、数据库设计

系统共 14 张表：

```text
tournament
team
player
user
tournament_team
squad
game
goal
comment
comment_like
news
team_info
member
work
```

设计要点：

- 统一使用 InnoDB、`utf8mb4` 和 `utf8mb4_unicode_ci`。
- 主键统一为 `id`，外键使用 `<实体>_id`。
- `team`、`player` 存稳定身份；每届变化的数据存入关联表。
- `tournament_team` 唯一约束防止同一球队重复参加同届赛事。
- `squad` 唯一约束防止同一球员同届代表多队、同队同号。
- `comment` 通过 `target_type + target_id` 多态挂载。
- `comment_like` 使用 `(comment_id, user_id)` 唯一索引防止重复点赞。
- 用户、球队、球员等历史主体被引用时由外键限制删除。

完整字段见 [`数据库表详细设计.md`](数据库表详细设计.md)。

## 七、关键业务流程

### 7.1 用户登录

```text
提交用户名和密码
  -> 查询 user 表
  -> password_verify 校验 bcrypt 哈希
  -> 建立前台会话
  -> 后台登录额外校验 role >= 1
```

### 7.2 留言发布

```text
用户提交留言
  -> 登录和 CSRF 校验
  -> 校验目标类型及目标记录
  -> 回复时校验父子目标一致
  -> user_id 取自当前登录身份
  -> 保存并跳回目标页面
```

### 7.3 留言删除

```text
作者或管理员发起删除
  -> 检查权限
  -> BFS 收集全部后代回复
  -> 事务内设置 status=1
  -> 前台有效查询排除整棵回复树
```

### 7.4 资讯发布

```text
管理员填写资讯
  -> 校验标题、状态和封面文件
  -> HTMLPurifier 清理正文
  -> 保存随机命名的封面
  -> 发布时设置 publish_time
  -> 前台只查询已发布记录
```

### 7.5 赛果与统计

```text
后台录入比赛与进球
  -> 保存 120 分钟比分和可选点球比分
  -> 保存进球归属、助攻与进球类型
  -> 首页/届次/球员页面聚合查询
  -> 图表按需读取统计接口
```

## 八、权限与安全

- 所有写操作使用 POST。
- 表单写操作启用 Yii2 CSRF 校验。
- 游客只能读取公开数据。
- 留言和点赞要求前台登录。
- 后台要求登录账号 `role >= 1`。
- 管理员与普通用户共用 `user` 表，通过角色区分权限。
- 用户提交内容输出时进行 HTML 转义。
- 资讯正文使用 HTMLPurifier。
- 上传文件同时校验扩展名、MIME 类型和大小。
- 上传文件使用服务器随机文件名。
- 图片路径限制在站内 `images/` 或 `uploads/`。
- 重复点赞、重复学号、重复球衣号由数据库唯一约束兜底。
- 删除操作需要二次确认，受外键约束保护的历史数据不能误删。
