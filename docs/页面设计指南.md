> 项目：世界杯数据门户（Yii2 + Bootstrap 3 + ECharts）。
> 色板与令牌见 `docs/设计改造-00-总纲.md` 第 11 节与 `theme.css`；质量底线见 `docs/界面设计规范.md`；本文件只讲**页面怎么组织**，不重复前者。

> **写作粒度**：规格只写意图、边界、验收；不写像素、列数、实现处方。详见 `docs/README.md`「文档写作约定」。

> **元规则**：本文件没写到的地方，按"信息是否好读"自行判断。规则是下限，不是上限；不要为了守规则牺牲可读性，也不要用"规范没写"拒绝合理的版式变化。

> **母版条款（2026-11 起）**：全站遵循 `docs/设计改造-00-总纲.md` 的母版与三类页面原型（索引 / 记录 / 表单）。版式数量、大号数字数量降为建议，不是硬约束；页面需要更强表达时，先说明理由并记录在总纲。质量底线（390 / 768 / 1440、无页面级横向溢出、键盘焦点、`prefers-reduced-motion`）仍然必须满足。

## C. 页面构成方法

1. **先写一句页面任务**：这个页面让访客完成什么？写不出来就先别开始画。
2. **首屏只回答两件事**：这是什么 + 下一步点哪。首屏不放第二个主张。
3. **每个 section 四段式**：小标题 → 一句说明 → 证据（表/图/卡）→ 一个动作或链接。
4. **视觉重量只分三级**：主标题 / 正文 / 辅助。需要更强，用字号和间距，不要加颜色。
5. **比较性数据同尺度、同颜色、同顺序**；不要在相邻图表里换配色或换图表类型。
6. **移动端是删信息，不是缩小信息**：次要列、次要说明在 <768 直接不显示。
7. **三种状态都要设计**：空 / 加载 / 出错。没数据的区块不要留成空白。
8. **收尾检查**：把整页截图缩到 25%，还能不能一眼看出主次？看不出就重做层级。

设计参考优先看仓库内 `docs/设计改造-01-感觉与工作流.md`；代码实例可看 <https://github.com/GoogleChrome/modern-web-guidance-src>。

## D. 新页面开工模板

先填完，再动代码：

```text
页面：<名称>
任务：<访客在这里完成什么>
首屏一句话：<h1 + 一句说明>
主操作：<动词 + 对象>
需要的证据：<表 / 图 / 卡，按重要性排序>
数据来源：<模型 / 接口 / 数据表>
与本站别处重复的信息：<列出来，这些只做链接不做重复展示>
状态：<空 / 加载 / 出错 分别显示什么>
```

这张卡里不确定的地方可以询问我,但你最好先给出我你预想的方案。

> 不写像素、列数、具体选择器；这些属于实现，写进带日期的实现记录。
