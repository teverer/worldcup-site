## C. 页面构成方法

1. **先写一句页面任务**：这个页面让访客完成什么？写不出来就先别开始画。
2. **首屏只回答两件事**：这是什么 + 下一步点哪。首屏不放第二个主张。
3. **每个 section 四段式**：小标题 → 一句说明 → 证据（表/图/卡）→ 一个动作或链接。
4. **视觉重量只分三级**：主标题 / 正文 / 辅助。需要更强，用字号和间距，不要加颜色。
5. **比较性数据同尺度、同颜色、同顺序**；不要在相邻图表里换配色或换图表类型。
6. **移动端是删信息，不是缩小信息**：次要列、次要说明在 <768 直接不显示。
7. **三种状态都要设计**：空 / 加载 / 出错。没数据的区块不要留成空白。
8. **宽行不要只靠两端**：一行里只有「名称」和「动作」时，`space-between` 会在中间留下大片空；把真正的数据（比分、年份、进度）放到行中央当锚点，或者把行宽收到信息密度够用为止。
9. **收尾检查**：把整页截图缩到 25%，还能不能一眼看出主次？看不出就重做层级。
10. **单届页里的跨届数据**：先写清“这是十一届”，再用金 / 银行或「本届」列把当前届标出来；同一块里不要把“本届”和“历届”两个分母混在一起。

## C.1 图表与数据边界（2026-11-24）

- **先选形**：比较大小用条形，占比用圆环或 100% 堆叠条，随时间用阶梯 / 折线；不要让一页三张图都长成同一种。
- **占比的分母固定**：图例、筛选或聚合不得在不说明的情况下重算其他项的百分比；图例只用于高亮时，不允许隐藏切片。
- **样本不足不画图**：原始 0 值仍留在表里；图位用一句「样本不足，不绘制…」加下一步链接，不用 0 值假装有图。
- **每张图有口径 + 数据表**：图旁一句口径说明，数据表可展开；颜色不单独承担含义，直接标签或图例至少有一个。
- **条形 / 柱状的提示只跟数据项走**：指针在条上才提示、才高亮；画布空白和整条类目带不响应。折线 / 时间序列才用整列提示（axis + 虚线指针）。
- **单位图先保证可数**：一个图形 = 一个单位（一个人、一个进球）时，单位数要能被一眼数清；不要为了显得数据多把点缩到 6–7px 以下。单位太多就分组、只列前 N，或换成聚合图。
- **榜类图只列前 N**：桌面约 10 行、窄屏约 8 行；其余不塞进画面。行内只留身份（旗、姓名、球队）和值，不再叠第二套坐标、分布条或图例。
- **一种颜色只承担一种含义**：金既标“本届”又标“第一名”时，读者分不清哪个是数据、哪个是装饰。第一名用位置、字重和留白，不再上第二层金色。
- **榜单即数据表**：每行已经有姓名、球队、数值时，不再重复一张展开表；保留每行可读的语义（列表 / 表格）即可。
- 参考：FootyCabin 球员页的 “Insufficient sample / no profile chart is drawn”、CricketStudio 的 sample floors、dataviz 的四类色彩职责（categorical / sequential / diverging / status）。

## C.2 届次图片（2026-11-25）

- 图片是那一届的证据和情绪，不是通用装饰；优先夺冠、经典瞬间、当届最有辨识度的画面，不用纯球场。
- 届次页：代表图铺满视口宽度（左右出血），年份 / 届次 / 冠军 / 决赛压在图上；图下是独立的 4 项数据带，可整块删；缺图退回夜场头。不做 100vh 全屏、不做轮播、不做悬停换图。
- 首页：小缩略图是可选层，默认低亮度；悬浮 / 聚焦才提亮；所有届次同权，不再把最新一届单独放大；用一个开关可整体回滚。
- 版权：每张图在届次页标作者 / 许可并链到文件页；CC BY-SA 的裁剪 / 调色衍生图按同许可共享；风险图单独列在 `docs/图片素材与许可.md`。

## D. 新页面开工模板

先填完，再动代码：

```text
页面：<名称>
任务：<访客在这里完成什么>
首屏一句话：<h1 + 一句说明>
主操作：<动词 + 对象>
需要的证据：<表 / 图 / 卡，按重要性排序>
数据来源：<模型 / 接口 / 数据表>
与本站别处重复的信息：<列出来，这些只做链接不做重复展示>
状态：<空 / 加载 / 出错 分别显示什么>
```

这张卡里不确定的地方可以询问我,但你最好先给出我你预想的方案。

> 不写像素、列数、具体选择器；这些属于实现，写进带日期的实现记录。
