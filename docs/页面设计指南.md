# 页面设计指南（给协作者与 AI 读）

> 项目：世界杯数据门户（Yii2 + Bootstrap 3 + ECharts）。
> 视觉身份、色板、组件、断点见 `docs/界面设计规范.md`；本文件只讲**页面怎么组织**，不重复前者。
> 改任何页面前，先读 C、D 两节。
>
> **元规则**：本文件没写到的地方，按"信息是否好读"自行判断。规则是下限，不是上限；不要为了守规则牺牲可读性，也不要用"规范没写"拒绝合理的版式变化。

## C. 页面构成方法

1. **先写一句页面任务**：这个页面让访客完成什么？写不出来就先别开始画。
2. **首屏只回答两件事**：这是什么 + 下一步点哪。首屏不放第二个主张。
3. **每个 section 四段式**：小标题 → 一句说明 → 证据（表/图/卡）→ 一个动作或链接。没有证据的 section 删掉。
4. **视觉重量只分三级**：主标题 / 正文 / 辅助。需要更强，用字号和间距，不要加颜色。
5. **一页最多两种版式**（如"列表 + 卡片网格"）。不要每个 section 换一种排法。
6. **一页最多一个大号数字**。多个数字并列时用小号 + 对齐，不要每个都做成 stat。
7. **比较性数据同尺度、同颜色、同顺序**；不要在相邻图表里换配色或换图表类型。
8. **移动端是删信息，不是缩小信息**：次要列、次要说明在 <768 直接不显示。
9. **三种状态都要设计**：空 / 加载 / 出错。没数据的区块不要留成空白。
10. **收尾检查**：把整页截图缩到 25%，还能不能一眼看出主次？看不出就重做层级。

## D. 新页面开工模板

先填完，再动代码：

```text
页面：<名称>
任务：<访客在这里完成什么>
首屏一句话：<h1 + 一句说明>
主操作：<动词 + 对象>
需要的证据：<表 / 图 / 卡，按重要性排序>
数据来源：<模型 / 接口 / 数据表>
与本站别处重复的信息：<列出来，这些只做链接不做重复展示>
状态：<空 / 加载 / 出错 分别显示什么>
```

这张卡能让 AI 少写一半无用区块，也能让你一眼看出它是不是跑偏了。
